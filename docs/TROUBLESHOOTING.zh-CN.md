# 排错手册

[English](TROUBLESHOOTING.md)

## 找不到自定义应用

核对 [Google 账户要求](https://support.google.com/gemini/answer/17209137)，使用英文官网。本地语言切换不会改变官网语言；工作台无法解锁账户尚未开放的功能。

## @ArgonDesk 只是普通文字

输入 @ 后，从官网菜单点选自己注册的应用。手拼名称和字体颜色都不证明连接。添加后刷新；混入旧 Insert 指令的对话建议另开任务。

## 输出黑色函数调用代码框后停住

它只是文本，不证明执行。原生调用应有真实工具卡片、结果及新增操作记录。不要在同一任务混用旧扩展；新建原生应用任务。已验证路径是英文 Task 和 Argon，官网开放情况可能变化。

## 为什么一直要 Allow

这是 Google 的人工写入确认，同意一次不等于后续全部免确认。让模型把同一文件的相关替换合并到 edit_file 的 edits 数组，减少调用。本软件不自动点击或关闭确认。

## 隧道 connecting，或者在线但文件没有变化

查看“连接设置 → 高级”的近期事件和当前错误，核对域名、令牌、网络。重连或成功公网响应可清除陈旧错误，但持续错误仍需排查。开启 TUN 不保证 ngrok 一定可达。

在线后还要确认文件访问启用、目录和权限正确、任务使用当前编号。握手和工具发现不等于成功读写；查看失败操作记录。

## TUN 与国内网站

仅凭 TUN 开关不能判断全局代理，应查看规则及实际命中。浏览器代理不会自动作用于 ngrok 进程。软件不改这些设置，详见[网络说明](NETWORKING.zh-CN.md)。

## 首次下载或签名失败

客户端不存在时，Start-ArgonDesk.cmd 调用 Install-Tunnel.ps1；需要访问官方下载站点并完成证书校验。核对错误、来源和 Windows 策略，不要跳过签名验证。公开 ZIP 有意不含 ngrok。

源码安装需 Node.js 22+、Setup.ps1 和 Build.ps1。保留完整解压目录。3008 端口被占用时先识别占用进程，不要结束所有 Node 进程。

## 换文件夹后请求被拒绝

这是预期行为：访问暂停、编号变化。先本地启用新工作区，再查询 workspace_info。只读状态即使模型请求也拒绝写入，不要为绕过拒绝而扩大授权目录。

## 路径或文件不支持

使用不超过 2 MiB 的普通 UTF-8 文本和相对路径。父目录、绝对路径、设备名、NTFS 附加流及链接被阻止。read_file 每次最多 1000 行。精确替换需唯一匹配；批量中任一项失败则整批不写，请重新读相关片段。

## 额度用尽或地址泄漏

模型额度与隧道额度独立，工作台无法重置；以提供方控制台为准。私人 URL 泄漏后本地更换密钥，再到官网更新地址。不要把原始状态和日志贴公开问题。

## 报告问题需要什么

软件及 Windows 版本、失败步骤、期望与实际表现、脱敏错误码、虚构样例复现。不要包含私人 URL、令牌、邮箱、真实路径、浏览器数据或个人文件正文。
